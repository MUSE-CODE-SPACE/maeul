# 레슨 1 — 구조화 응답: 게임이 먹는 건 텍스트가 아니다

📄 대응 파일: `maeul/schema.py`

## 핵심 통찰
초보가 LLM으로 NPC를 만들 때 첫 실수: **대사 문자열 하나만 받는다.** 하지만 게임 엔진은
그 이상이 필요하다. 같은 "…괜찮아."라도 **무서워하며** 말하는지 **담담하게** 말하는지에 따라
표정·애니메이션·카메라가 달라진다.

그래서 Maeul의 NPC 한 마디는 항상 이 구조다:

```python
@dataclass
class Reply:
    line: str                 # 화면에 띄울 대사
    emotion: str = "neutral"  # 표정/애니메이션 트리거 (고정된 9종)
    action: str = None        # 무대 지시: "뒷걸음질친다", "북쪽을 가리킨다"
    topic: str = None         # 짧은 태그: "홍수", "우물"
    facts: list = []          # RAG 근거 (환각 방지 추적)
```

`emotion`을 **고정 집합**(`neutral, happy, sad, angry, scared, surprised, tired, excited, worried`)으로
둔 게 포인트다. 엔진 쪽에서 `animator.SetTrigger(reply.emotion)` 한 줄로 매핑되게.

## 어려운 부분: 모델은 깨끗한 JSON을 안 준다
LLM에게 "JSON으로 답해"라고 해도, 마크다운 펜스를 두르거나, 앞뒤로 수다를 붙이거나,
**토큰 한도에서 잘려서** 닫는 중괄호가 없기도 하다. 실제로 우리 첫 테스트에서 이렇게 잘렸다:

```
{"line": "아이고, 어서 와요! 오늘 바람 마을은 날씨 참 좋아요. 약초
```

닫는 `}`가 없으니 `json.loads`는 실패한다. 그래서 `parse_reply`는 **3단 방어**를 한다:
1. 완전한 `{...}` 블록을 JSON 파싱 시도
2. 실패하면 **정규식으로 `"line"` 값만 뽑기** (잘려도 따옴표 안 내용은 건진다)
3. 그래도 없으면 원문 전체를 대사로

```python
_STR_FIELD = r'"{key}"\s*:\s*"((?:[^"\\]|\\.)*)'   # 닫는 따옴표 없어도 매칭
```

이 관용적 파서가 **체감 안정성의 8할**이다. 로컬 소형 모델일수록 출력이 지저분해서 더 그렇다.

## 직접 해보기
1. `parse_reply('```json\n{"line":"안녕","emotion":"happy"}\n```')` 를 호출해 펜스가 벗겨지는지 확인.
2. 일부러 잘린 문자열 `'{"line":"오늘 날씨가'` 를 넣어보고 `line`이 건져지는지 보라.
3. `emotion`에 없는 값(`"삐침"`)을 넣으면 `neutral`로 정규화되는지 확인. (엔진이 모르는 트리거를 받지 않도록.)
