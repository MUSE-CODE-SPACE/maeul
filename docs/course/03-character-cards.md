# 레슨 3 — 캐릭터 카드: 성격을 데이터로

📄 대응 파일: `maeul/character.py` · 예시: `examples/village/mira.json`

## 성격은 코드가 아니라 파일이다 (원칙 4)
기획자가 프로그래머를 부르지 않고 새 주민을 추가할 수 있어야 한다. 그래서 성격을
**카드**로 뺀다:

```json
{
  "name": "미라", "role": "약초상", "age": 34,
  "persona": "어릴 때 강 범람으로 부모를 잃어 물을 무서워한다.",
  "traits": ["따뜻함", "수다스러움", "겁이 많음"],
  "speech_style": "다정하고 말이 많다. 존댓말·반말을 섞는다.",
  "fears": ["홍수", "깊은 물", "강"],
  "catchphrases": ["아이고, 어서 와요"],
  "knowledge": ["약초와 물약", "옛날 강 범람 이야기"],
  "relationships": {"토르": "옆집 대장장이, 츤데레 친구"},
  "anxiety": 0.4
}
```

이 카드가 왜 강력한가? `fears`에 "홍수"를 넣었기 때문에, 나중에 월드에 홍수 이벤트가 뜨면
**미라만 유독 무서워한다.** 성격과 상황이 데이터로 만나 반응이 나온다.

## 카드 → 페르소나 문장
모델은 JSON을 그대로 읽지 않는다. `persona_block()`이 카드를 **자연어 페르소나**로 렌더한다:

```
You are 미라, the village 약초상 (age 34).
어릴 때 강 범람으로 부모를 잃어 물을 무서워한다.
Personality: 따뜻함, 수다스러움, 겁이 많음.
You are afraid of: 홍수, 깊은 물, 강.
People you know: 토르 is 옆집 대장장이, 츤데레 친구.
```

이게 매 턴 시스템 프롬프트의 맨 앞에 들어간다.

## 설계 결정
- **JSON 기본, YAML 옵션**: JSON은 의존성 0(원칙 2). YAML은 손으로 쓰기 편하지만 `pip install
  maeul[yaml]`이 필요하니 옵션으로. 로더는 확장자로 자동 분기.
- **`anxiety` (0~1)**: 캐릭터의 *기본* 불안도. 겁많은 미라는 0.4, 용감한 토르는 0.2. 런타임에
  재해가 이 값을 밀어올린다 (레슨 7). 성격 = 시작점, 상황 = 변화량.
- **`knowledge`**: 이 주민이 아는 주제. 대장장이에게 약초 물으면 얼버무리게 하는 힌트.

## 직접 해보기
1. 새 주민 `baker.json`(빵집 주인)을 만들어라. `fears`에 "빵이 타는 것", `catchphrases`에
   말버릇 하나. `--who baker`로 대화해보라.
2. 미라의 `anxiety`를 0.4 → 0.05로 낮추고 같은 홍수 상황에서 반응이 덜 겁먹는지 관찰하라.
