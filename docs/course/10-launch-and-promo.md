# 레슨 10 — 오픈소스로 공개하고 홍보하기 (별 받는 법)

📄 대응: 저장소 전체 + `docs/PROMO.md`

좋은 코드를 만드는 것과 **사람들이 알게 하는 것**은 별개의 기술이다. Public 저장소로 명성을
얻으려면 홍보도 설계해야 한다.

## 별을 부르는 5요소
1. **한 줄 훅**: "무료·온디바이스 게임 NPC LLM 엔진." 30초 안에 뭔지, 왜 다른지 전달.
2. **첫 5분 경험**: `pip install` → 3줄 → 실제 대사. README 위쪽에 **바로 복붙 가능한** 퀵스타트.
3. **보여주기 > 말하기**: 미라가 평온→홍수에서 감정이 바뀌는 **실제 출력**을 README에 박아라.
   가능하면 30초 데모 GIF/영상. (사용자님은 영상 채널이 있으니 강력한 무기.)
4. **비교표**: 기존 대안(스크립트 트리·클라우드 SaaS) 대비 빈자리를 표로. 왜 이게 필요한지 각인.
5. **진입장벽 0**: MIT, 의존성 최소, 예제 마을 포함. "이거 내 프로젝트에 5분이면 붙이겠다" 느낌.

## 어디에 올리나 (채널별 톤)
- **Show HN** (Hacker News): 담백하게. "Show HN: Maeul – a money-free, on-device LLM engine for
  game NPCs". 기술적 정직함(한계도 인정)이 먹힌다.
- **r/LocalLLaMA**: 로컬·무료·Ollama 각도. 온디바이스 커뮤니티가 좋아한다.
- **r/gamedev, r/Unity3D**: 게임 개발자 각도. "NPC가 상황 따라 반응", 유니티 스니펫.
- **X/트위터 스레드**: 데모 영상 + 실제 대사 스크린샷. 훅→문제→해법→퀵스타트→링크.
- **한국 커뮤니티**(GeekNews, 커뮤니티): "마을"이라는 한국어 이름과 스토리를 살려라.

실제 복붙용 문안은 `docs/PROMO.md`에 다 써뒀다.

## 타이밍 & 지속
- 첫 커밋에 다 쏟지 말고, **데모가 진짜 도는 순간** 공개하라 (우리는 그렇게 했다).
- 공개 후 첫 몇 시간 댓글에 **빠르게 응답**하는 게 별점 곡선을 만든다.
- 로드맵을 README에 두면 "미완성"이 아니라 "성장 중"으로 읽힌다.

## 정직함이 곧 신뢰
한계(한국어 TF-IDF 검색의 약점 등)를 **먼저 밝히면** 오히려 신뢰가 오른다. 과장은 첫 이슈에서
들통난다. 우리는 강좌·README에 트레이드오프를 그대로 적었다.

## 직접 해보기
1. `docs/PROMO.md`의 Show HN 문안을 여러분 프로젝트에 맞게 30초 안에 이해되게 다듬어라.
2. 30초 데모(터미널 대화 or 유니티 마을)를 녹화해 README 최상단에 걸어라. 전환율이 가장 크게 오른다.
